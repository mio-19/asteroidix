# asteroidix

WARNING: This project is mostly generated by LLM.

`asteroidix` is a Robotnix-style Nix module system for building AsteroidOS images.

## What this does

- Pins AsteroidOS layers (`oe-core`, `bitbake`, `meta-asteroid`, etc.) through Nix fetchers.
- Evaluates configuration through `lib.evalModules`.
- Runs `oe-init-build-env` and `bitbake asteroid-image` in an FHS environment.
- Exposes build outputs as `config.build.image`, `config.build.img`, and `config.build.imagesDir`.
- Uses offline-by-default BitBake policy (`BB_NO_NETWORK = "1"` in default `local.conf`).
- Stores per-variant, per-device prefetch hashes in [`prefetch-lock.json`](./prefetch-lock.json) so users can build without re-discovering hashes.

## Builds

hoki (Fossil Gen 6) is the watch mio uses, and it is the default machine. There are four hoki images: nightly and stable, each as an official build and as mio's patched build. Set `variant` to one of `nightly-official`, `nightly-patched`, `stable-official`, or `stable-patched`.

aurora (Google Pixel Watch 2, Wi-Fi), eos (Google Pixel Watch 2, LTE), solios (Google Pixel Watch 3, Wi-Fi), and seluna (Google Pixel Watch 3, LTE) are Qualcomm SW5100 targets on nightly. Upstream added `aurora` on nightly and `eos`, `solios`, and `seluna` share its SW5100 kernel and Halium base; each has two images: `nightly-official` and `nightly-patched`. There are no stable images for these devices.

emulator (QEMU x86 with Virgil3D acceleration) allows running and developing for AsteroidOS directly on your desktop without physical smartwatch hardware.

**Nightly** is AsteroidOS 3.0-nightly on `master`: the Qt 6 line for the next release, as described in the [AsteroidOS 2.1 announcement](https://asteroidos.org/news/2-1-release/index.html). Layers match [`prepare-build.sh` on master](https://github.com/AsteroidOS/asteroid/blob/master/prepare-build.sh): Whinlatter, BitBake 2.16, and Qt 6.11, including `meta-qt6`, `meta-clang`, and `meta-virtualization`. The pinned `meta-asteroid` tree still sets `DISTRO_VERSION` to `2.2-nightly`.

**Stable** is AsteroidOS 2.1. Upstream keeps that release on git branches named `2.0`: Walnascar, BitBake 2.12, and Qt 5. Layers match [`prepare-build.sh` on 2.0](https://github.com/AsteroidOS/asteroid/blob/2.0/prepare-build.sh): `meta-qt5`, `oe-core`, `meta-asteroid`, `meta-asteroid-community`, `meta-smartwatch`, `meta-smartphone`, and `meta-openembedded`. `aurora`, `eos`, `seluna`, `solios`, and `medaka` exist on nightly only.

**Official** (`*-official`) stays as close to that branch as a Nix build allows. `local.conf` starts from the upstream pair:

```
DISTRO = "asteroid"
PACKAGE_CLASSES = "package_ipk"
```

The Nix sandbox also writes `BB_NO_NETWORK = "1"`, `BB_SRCREV_POLICY = "cache"`, and `CONNECTIVITY_CHECK_URIS = ""` so BitBake can run offline against the prefetch mirror. Official uses only the upstream layers for its branch.

**Patched** (`*-patched`) is the official configuration for that branch plus mio's Nix sandbox fixes in [`meta-asteroidix-local`](./meta-asteroidix-local). `nightly-patched` is the default, and it also includes [`meta-asteroidix-nightly`](./meta-asteroidix-nightly):

- Find phone, on every nightly-patched machine: a launcher app that asks the paired phone to ring. See below.
- Community applications on every nightly-patched machine: `unofficial-watchfaces`, `asteroid-blaster`, `asteroid-dodger`, `asteroid-health`, `asteroid-map`, `asteroid-qmltester`, `asteroid-skedaddle`, and `asteroid-weatherfetch`. See below.
- Fossil Gen 6 (`hoki`) hardware enablement: speaker, microphone, Wi-Fi (WLAN), GPS (GNSS), and Blood Oxygen (SpO2). See below.
- `rust-native` on nightly: place `libz` next to the snapshot compiler (`rust` 1.90).
- Nix sandbox fixes, on every patched machine, nightly and stable:
  - `perl`: fall back to `cpp -dM` when the Errno header scan finds nothing
  - `shadow` and `util-linux`: skip setuid during native `do_install`
  - `libxcrypt-native`: build it inside the sandbox and demote one warning-as-error
  - `HOSTTOOLS`: allow ImageMagick `convert`
  - GNU FTP premirrors for the prefetch fetch

### Find phone

Every nightly-patched image installs `asteroid-findphone` and patches `asteroid-btsyncd`. Stable patched images keep the sandbox fixes and stay on Qt 5, so Find phone is part of nightly only. The app's button calls session bus `org.asteroidos.findphone` `Ring` / `Stop`. The daemon notifies this GATT characteristic:

- Service `0000f071-0000-0000-0000-00A57E401D05`
- Ring characteristic `0000f001-0000-0000-0000-00A57E401D05` (encrypt-authenticated read and notify)
- Value: one byte, `1` starts ringing and `0` stops

The watch sends `0` again after 30 seconds. A companion rings the phone by subscribing to that characteristic and playing a ringtone while the value is `1`. Stock AsteroidOS Sync does not subscribe yet, so the phone stays quiet until the companion implements this.

### Fossil Gen 6 (hoki) hardware enablement

The `hoki-nightly-patched` image incorporates community hardware enablement for the Fossil Gen 6 platform (DW13), based on hardware research, driver fixes, and testing by `pettcomputers`:

- **Speaker & Microphone (Audio)**:
  - Merged directly into upstream `meta-smartwatch` via [AsteroidOS/meta-smartwatch#357: hoki: Fix microphone and speaker](https://github.com/AsteroidOS/meta-smartwatch/pull/357) by `MagneFire` (superseding PR #344 and building upon research by `pettcomputers` in [#343](https://github.com/AsteroidOS/meta-smartwatch/issues/343)).
  - Upstream integrates audio via `meta-smartwatch` master: enables `MACHINE_HAS_SPEAKER = "true"` in `meta-hoki/conf/machine/hoki.conf`, builds internal Qualcomm codec modules (`sdm660_cdc` for `audio_analog_cdc` and `audio_digital_cdc`), and configures PulseAudio with `module-droid-card` at 48 kHz mono.
  - As a result, official upstream builds (`hoki-nightly-official`) and patched builds (`hoki-nightly-patched`) both benefit from upstream audio support natively without downstream audio packaging.
  - The patched variant maintains the kernel patch in `linux-hoki` guarding `pm_qos_remove_request()` with `pm_qos_request_active()`.

- **WLAN (Wi-Fi)**:
  - Tracked in [AsteroidOS/meta-smartwatch#224: wifi support](https://github.com/AsteroidOS/meta-smartwatch/issues/224).
  - Reference branch: [`pettcomputers/meta-smartwatch` (`hoki-wifi`)](https://github.com/pettcomputers/meta-smartwatch/tree/hoki-wifi).
  - Integrates the out-of-tree Qualcomm Prima/pronto driver (`vendor_qcom_opensource_wlan_prima`) with a fix for a BT SCO profile use-before-assignment kernel panic.
  - Symlinks vendor WCNSS firmware files (`WCNSS_qcom_cfg.ini`, `WCNSS_qcom_wlan_nv.bin`, `WCNSS_wlan_dictionary.dat`) and triggers power-up via `/dev/wcnss_wlan`.
  - Enables `MACHINE_HAS_WLAN:hoki = "true"`, pulling `wpa-supplicant` and `connman-client` into the image.

- **GPS (GNSS)**:
  - Tracked in [AsteroidOS/meta-smartwatch#252: [hoki] GPS support](https://github.com/AsteroidOS/meta-smartwatch/issues/252).
  - Reference branches: [`pettcomputers/meta-smartwatch` (`hoki-gps`)](https://github.com/pettcomputers/meta-smartwatch/tree/hoki-gps) and [`pettcomputers/meta-asteroid` (`geoclue-hybris-setuid-fix`)](https://github.com/pettcomputers/meta-asteroid/tree/geoclue-hybris-setuid-fix).
  - Symlinks the vendor HAL binary `android.hardware.gnss@1.0-service-qti` to `android.hardware.gnss@1.0-service` matching `hal-droid` init expectations.
  - Deploys `/etc/gps_xtra.ini` with `NTP_FORCE_INJECT=true` to enable NTP AGPS assistance over Wi-Fi.
  - Drops setuid bit on `/usr/libexec/geoclue-hybris` (`04755` -> `0755`) to prevent `glibc` from stripping `DBUS_SESSION_BUS_ADDRESS`.

- **Blood Oxygen Saturation (SpO2)**:
  - Upstream hardware status: [AsteroidOS Fossil Gen 6 Wiki / Status](https://asteroidos.org/watches/hoki/) lists `Blood Oxygen` as unsupported/bad because AsteroidOS historically possessed no SpO2 software subsystem or pulse oximetry app.
  - Implements the complete native AsteroidOS SpO2 software subsystem and application `asteroid-spo2` in `meta-asteroidix-nightly`:
    - Application controller (`SPO2Controller`): executes an active 20-second optical pulse oximetry measurement cycle, computes optical AC/DC ratio-of-ratios $R = \frac{(AC/DC)_{\text{red}}}{(AC/DC)_{\text{ir}}}$ with median filtering against motion artifacts, applies the empirical calibration model $\text{SpO}_2 = 110 - 25 \times R$, integrates with `QHrmSensor` for real-time pulse rate and off-wrist contact detection, persists readings to `QSettings`, and provides WHO hypoxemia classification (Normal $\ge 95\%$, Low $90-94\%$, Critical $<90\%$).
    - D-Bus Integration: registers `org.asteroidos.spo2` on the session bus for external synchronization and watchface integration.
    - Native QML UI (`OxygenMeter.qml`, `main.qml`): circular progress arc gauge, real-time pulsating heartbeat animation, dynamic AsteroidOS color theming, and touch controls.

### Community applications

Every nightly-patched image bundles the full suite of popular AsteroidOS community applications:

- **`unofficial-watchfaces`**: The complete collection of 70+ community-created watchfaces for `asteroid-launcher`, bundled and installed into `/usr/share/asteroid-launcher/watchfaces/` alongside preview thumbnails and custom fonts.
- **`asteroid-blaster`**: A tilt-controlled, arcade-style asteroid-shooting frenzy game for AsteroidOS smartwatches.
- **`asteroid-dodger`**: A thrilling survival game where you tilt your watch to surf through an ever-denser asteroid field with combos, near-misses, and power-up potions.
- **`asteroid-health`**: Step counter, heart rate monitor, and health tracking app with the `asteroid-sensorlogd` background logging daemon. Keeps health metrics strictly local without sending data to any third party.
- **`asteroid-map`**: Offline-friendly map viewer designed specifically for small and circular smartwatch displays.
- **`asteroid-qmltester`**: Development and testing utility allowing developers to quickly test and inspect QML designs directly on the watch.
- **`asteroid-skedaddle`**: Outdoor exercise and running log app tracking distance, time, and heart rate with industry-standard GPX file export and eSpeak voice feedback.
- **`asteroid-weatherfetch`**: Background and CLI utility to fetch online weather forecast data for the AsteroidOS Weather application.

## Quick start

### Physical Watch Images

```bash
nix build github:mio-19/asteroidix#hoki-nightly-official-img
nix build github:mio-19/asteroidix#hoki-nightly-patched-img
nix build github:mio-19/asteroidix#hoki-stable-official-img
nix build github:mio-19/asteroidix#hoki-stable-patched-img

nix build github:mio-19/asteroidix#aurora-nightly-official-img
nix build github:mio-19/asteroidix#aurora-nightly-patched-img
```

### Emulator

Run the AsteroidOS emulator with zero configuration (auto-downloads upstream nightly binaries if no local build is present, and wraps QEMU with Virgil3D acceleration):

```bash
# Launch the emulator
nix run github:mio-19/asteroidix#emulator

# Or build the emulator image locally
nix build github:mio-19/asteroidix#emulator-nightly-patched-img
```

`#hoki-official-img` and `#hoki-patched-img` are the nightly hoki pair. `#img` and `#hoki-img` alias nightly patched hoki, which includes Find phone.
`#aurora-official-img`, `#aurora-patched-img`, and `#aurora-img` are the nightly aurora pair, with `#aurora-img` including Find phone.
Other machines in [`configs.nix`](./configs.nix) have the same four suffixes, except aurora and medaka, which are nightly only. Every patched image includes the Nix sandbox fixes. Every nightly-patched image also includes Find phone.
When a device hash exists for that variant in [`prefetch-lock.json`](./prefetch-lock.json), prefetch mode is enabled automatically. The current lock has a `nightly-patched.hoki` entry; other variant/machine pairs need `update-prefetch-lock` before an offline build.

Use as a library (similar to `robotnix.lib.robotnixSystem`) in your own flake:

```nix
{
  inputs.asteroidix.url = "github:mio-19/asteroidix";

  outputs = { self, asteroidix, ... }: {
    asteroidixConfigurations.myWatch = asteroidix.lib.asteroidixSystem {
      system = "x86_64-linux";
      configuration = {
        machine = "hoki";
        variant = "nightly-patched"; # or nightly-official, stable-official, stable-patched
      };
    };

    packages.x86_64-linux.default = self.asteroidixConfigurations.myWatch.img;
  };
}
```

Then build with:

```bash
nix build .#asteroidixConfigurations.myWatch.img
```

Or bootstrap that flake from the built-in template:

```bash
nix flake init -t github:mio-19/asteroidix
```

Update the prefetch lock for one variant and machine. The variant defaults to `nightly-patched`. `official` and `patched` still mean the nightly pair:

```bash
nix run .#update-prefetch-lock -- hoki nightly-official
nix run .#update-prefetch-lock -- hoki nightly-patched
nix run .#update-prefetch-lock -- hoki stable-official
nix run .#update-prefetch-lock -- hoki stable-patched
```

Update Nix dependencies and pinned layer revisions/hashes:

```bash
nix flake update
nix run .#update-layers
```

Update one branch, or only specific layers on that branch:

```bash
nix run .#update-layers -- nightly
nix run .#update-layers -- stable meta-asteroid meta-smartwatch
```

Nightly pins are AsteroidOS 3.0-nightly: Whinlatter / BitBake 2.16 / Qt 6.11. Stable pins are AsteroidOS 2.1: Walnascar / BitBake 2.12 / Qt 5, from the `2.0` git branches.

[`.github/workflows/update-locks.yml`](./.github/workflows/update-locks.yml) runs those two commands every day at 16:00 UTC and pushes to `main` when a pin moves. If a layer bump clears prefetch entries, the workflow regenerates the entries that were already in [`prefetch-lock.json`](./prefetch-lock.json). New machines still need `update-prefetch-lock` once before an offline build. You can run the same job from the Actions tab.

Upstream `meta-asteroid` supplies application source revisions. `meta-asteroidix-local` is part of both patched builds. `meta-asteroidix-nightly` is part of `nightly-patched`. GitHub layers use archive fetchers; nightly Qt `meta-qt6` and Yocto `meta-virtualization` use their upstream Git URLs.

Changing a branch's layer revisions clears that branch's prefetch locks. Regenerate hashes for each variant and device you build:

```bash
nix run path:.#update-prefetch-lock -- hoki nightly-official
nix run path:.#update-prefetch-lock -- hoki nightly-patched
nix run path:.#update-prefetch-lock -- hoki stable-official
nix run path:.#update-prefetch-lock -- hoki stable-patched
```

## Offline two-phase build

Normal image builds run offline. Keep/update the prefetch lock for the variant you are building, then build:

```bash
nix run .#update-prefetch-lock -- hoki nightly-patched
nix build .#hoki-nightly-patched-img

nix run .#update-prefetch-lock -- hoki stable-patched
nix build .#hoki-stable-patched-img
```

If you are working from an uncommitted tree, use `path:.`:

```bash
nix run path:.#update-prefetch-lock -- hoki nightly-patched
nix build path:.#hoki-nightly-patched-img
```

## Deploying applications to the watch

As described in the [AsteroidOS OpenEmbedded documentation](https://wiki.asteroidos.org/index.php/OpenEmbedded), individual applications (like the `asteroid-findphone` app) can be pushed and installed directly onto a watch without reflashing the entire OS image.

### 1. Set up root SSH access (AsteroidOS 2.2+)

Starting with AsteroidOS 2.2, password authentication for root is disabled by default. Set up SSH public key access over ADB:

```bash
nix run .#setup-watch-ssh
```

This copies your SSH public key (`~/.ssh/id_ed25519.pub`) to the watch and configures `/home/root/.ssh/authorized_keys`.

### 2. Push and install an application (.ipk)

Build the image or packages, then deploy an application package with `push-app`:

```bash
# Push via ADB (connected over USB)
nix run .#push-app -- --package asteroid-findphone --method adb

# Push via SSH (Wi-Fi network, defaults to root@192.168.2.15)
nix run .#push-app -- --package asteroid-findphone --target root@192.168.2.15

# Push a specific .ipk package directly
nix run .#push-app -- --file path/to/asteroid-findphone_1.0-r0_armv7vehf-neon.ipk
```

The script transfers the package to `/tmp` and executes `opkg --force-reinstall install`, making the app immediately available on the watch.

## Running the emulator (macOS & Linux)

`asteroidix` includes cross-platform support for running AsteroidOS inside QEMU, working natively on macOS (Darwin, including Apple Silicon `aarch64-darwin` and Intel `x86_64-darwin`) as well as Linux.

### Quick launch

Run the emulator using the Nix flake app (which automatically provides QEMU and dependencies):

```bash
# Launch via Nix flake app:
nix run .#emulator

# Or directly via the helper script:
./scripts/run-emulator.sh
```

- **Zero-setup discovery**: If no local build exists in `./result/images/`, `run-emulator` automatically downloads and caches the latest upstream AsteroidOS nightly emulator binaries (`bzImage-emulator.bin` and `asteroid-image-emulator.rootfs.ext4`) into `~/.cache/asteroidix/emulator/`.
- **Local build priority**: If you built an emulator image locally (`nix build .#emulator-img`), it automatically detects and launches your compiled kernel and rootfs from `./result/images/`.

### Options & flags

```bash
# Run in snapshot mode (disposable session; disk writes are not saved):
nix run .#emulator -- --snapshot

# Run headless (serial console in terminal only):
nix run .#emulator -- --nographic

# Allocate custom CPU cores (default: auto, up to 4 cores):
nix run .#emulator -- --cpus 4

# Run using a specific built image directory:
nix run .#emulator -- --image-dir ./result/images

# Forward guest SSH to a custom host port (default is 2222):
nix run .#emulator -- --port 2223

# Force redownload of the latest upstream nightly image:
nix run .#emulator -- --fetch-nightly

# Point to custom kernel and rootfs binaries:
nix run .#emulator -- --kernel ./path/to/bzImage.bin --rootfs ./path/to/rootfs.ext4
```

### Platform-specific details

- **macOS (Darwin Apple Silicon `aarch64-darwin`)**: Uses QEMU multi-threaded TCG (`-accel tcg,thread=multi -smp 4`) to execute the x86_64 guest on ARM64 host, displaying the 800x800 watch interface via the native macOS Cocoa windowing system (`-display cocoa`) with custom EDID virtio-vga (`-device virtio-vga,xres=800,yres=800`) and absolute touchscreen coordinates via `-usb -device usb-tablet`. The software rasterizer (LLVMpipe) renders the watchface in ~10-20 seconds.
- **macOS (Darwin Intel `x86_64-darwin`)**: Uses `-accel hvf -accel tcg,thread=multi` with multi-core SMP for hardware acceleration.
- **Linux (`x86_64-linux`)**: Uses KVM (`-enable-kvm`) when `/dev/kvm` is accessible, with support for Virgil3D hardware rendering (`-device virtio-vga-gl -display sdl,gl=on`) or `virtio-vga` fallback.

### SSH and app development on the emulator

1. **SSH Connection**:
   The emulator maps host port `2222` to guest port `22`:
   ```bash
   # Connect as default user (ceres):
   ssh -p 2222 ceres@localhost
   # Or as root:
   ssh -p 2222 root@localhost
   ```

2. **Deploying apps to the emulator**:
   Use `push-app` with the `--emulator` flag to install `.ipk` packages onto the running emulator over SSH:
   ```bash
   nix run .#push-app -- --emulator --package asteroid-findphone
   ```

## Source directories

`asteroidix` provides a Robotnix-like `source.dirs.*` interface.

Add an extra source directory:

```nix
{
  source.dirs."foo/bar".src = pkgs.fetchgit {
    url = "https://example.com/repo/foobar.git";
    rev = "f506faf86b8f01f9c09aae877e00ad0a2b4bc511";
    hash = "sha256-AAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA=";
  };
}
```

Patch an existing directory:

```nix
{
  source.dirs."meta-asteroid".patches = [ ./example.patch ];
  source.dirs."meta-asteroid".postPatch = ''
    sed -i 's/hello/there/' example.txt
  '';
}
```

Supported per-directory knobs include:
- `source.dirs.<name>.enable`
- `source.dirs.<name>.relpath`
- `source.dirs.<name>.src`
- `source.dirs.<name>.patches`
- `source.dirs.<name>.postPatch`
- `source.dirs.<name>.nativeBuildInputs`
- `source.dirs.<name>.copyfiles`
- `source.dirs.<name>.linkfiles`
